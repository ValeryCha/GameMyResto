# Пиковый час — финальная редакция

Пик — стресс-тест спроса, очереди и пропускной способности. Документ не описывает реализацию кода.

## 1. Цикл и предупреждение

- Цикл: **180 тиков**.
- Пик: первые **60 тиков**.
- Предупреждение: за **10 тиков**, в тиках 170–179 цикла.
- `peakFactor = 1.50` применяется к исходному спросу до общего капа `arrivalRate ≤ throughput × 1.3`.
- Во время предупреждения HUD показывает обратный отсчёт и лимитирующее звено.

## 2. Статистика

Для каждого `peakId` сохраняются:

| Поле | Значение |
|---|---|
| `startedAtTick` | Начало пика |
| `arrived` | Новые попытки прихода |
| `seated` | Получившие место |
| `served` | Полностью обслуженные с оплатой |
| `unhappy` | Все недовольные уходы |
| `queueRejected` | Отказы полной очереди |
| `queueTimeout` | Таймауты очереди |
| `revenue` | Выручка и чаевые |
| `bonusCoins` | Итоговая награда |

```text
peakGuests = arrived + carriedIn
serviceRatio = served / max(1, served + unhappy)
completion = (served + unhappy) / max(1, peakGuests)
```

`carriedIn` — активные гости на начало пика. Оставшиеся незавершёнными в конце пика не становятся автоматически недовольными.

Для награды используется `serviceRatio`. `completion` отдельно показывает долю завершённых гостей. До конца пика HUD показывает только «обслужено X · недовольных Y», без финального процента.

## 3. Награды

### Чаевые

- Множитель **×1.5** применяется к текущему `tipMultiplier`.
- Учитывается только оплата, завершённая во время пика.
- Базовая цена блюда не умножается.

### Итог пика

| Результат | Условие | Награда |
|---|---|---|
| Отличный | `serviceRatio >= 0.90`, `queueRejected + queueTimeout = 0`, `served >= 5` | `bonusCoins = 500 + 100 × level`, `bonusXP = 50` |
| Хороший | `serviceRatio >= 0.75`, `served >= 3` | `bonusCoins = 250 + 50 × level`, `bonusXP = 20` |
| Пройден | Остальные случаи | Только выручка и чаевые |

`perfect = true`, если:

- `peakGuests >= 5`;
- `unhappy = 0`;
- все завершившие цикл гости обслужены;
- нет `queueRejected` и `queueTimeout`.

`perfect` используется заданиями и не даёт третью денежную награду.

Награда выдаётся один раз на `peakId`. `rewardedPeakIds` содержит не более 30 последних значений.

## 4. Связь с очередью

- Пик не добавляет места, блюда или сотрудников.
- Кап спроса ограничивает перегрузку 30% сверх `throughput`.
- Полная очередь и таймауты применяют штрафы -10 и базово -20 до -50 рейтинга.
- Неуспешный пик не отнимает прошлую выручку и не снижает уровень.
- Подготовленные 5/5 официанты и стойки всё равно требуют достаточной кухни и мест.

## 5. HUD

- До пика: «Пик через N».
- Во время: оставшееся время, обслуженные и недовольные.
- После: краткая заменяемая плашка результата; подробный итог в прогрессе.
- Полоса уровня не меняется.
- Тач-цели ≥ 44×44 и доступные имена сохраняются.

## 6. Сохранение

```text
peakState {
  activePeakId: number | null
  rewardedPeakIds: number[]
  current: PeakStats | null
  last: PeakResult | null
}
```

- Старый сейв получает нейтральную структуру.
- При загрузке в середине пика статистика начинается с текущего тика без выдуманных прошлых событий.
- Награда не повторяется после перезагрузки.
- Видимость плашки и анимации не сохраняются.

## 7. Будущие сценарии приёмки

- Предупреждение начинается ровно за 10 тиков.
- Пик длится 60 тиков и применяет множитель 1.5 до капа.
- Чаевые ×1.5 применяются один раз.
- Награда не дублируется по `peakId`.
- `serviceRatio` и `completion` не смешиваются.
- Очередь меняет статистику только по фактическим уходам.
- При 1/1 кухни и высоком спросе симуляция продолжает работать с ограниченной очередью.

## 8. Открытый вопрос

1. **Итоговая плашка:** показывать автоматически на 5–8 секунд или оставить только в прогрессе. Блокирует реализацию: нет; рекомендуется короткая плашка и запись в прогрессе.
