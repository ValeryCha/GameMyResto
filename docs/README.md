# Трекер промптов проекта «Restaurant City / Мой ресторан»

Здесь фиксируются все промпты для Kimi, их статус, зависимости и результат. 
Каждый промпт — отдельный файл в `docs/prompts/`, ответ Kimi — в `docs/prompts/responses/`.

## Обозначения статусов

- ⏳ **Draft** — текст готов, но отправлять рано (есть зависимость)
- 🟡 **Ready** — можно отправлять, зависимости закрыты
- 🔵 **Sent** — отправлен Kimi, ответа пока нет
- 🟣 **Review** — ответ получен, идёт проверка
- ✅ **Accepted** — принят, изменения в игре
- 🔧 **Needs Patch** — принят частично, требуется точечная доработка
- ❌ **Reverted** — откачен, нужен перезапуск

## Префиксы

- **UI-N** — визуал, раскладка, CSS, анимации, магазин, HUD. Не трогает `simulation`.
- **LOGIC-N** — механики, формулы, задания, система гостей, сохранения.
- **LOGIC-BN** — bug-fix выполняется раньше LOGIC-N с тем же номером.

## Ключевые решения, которые нельзя забыть

Зафиксированы в промптах, чтобы новые прогоны их не сломали:

- **HUD — гибрид, не копия.** 4 наших показателя + полоса опыта. Не добавлять премиум-валюту, кубок со звёздами, соцкнопки.
- **5 кнопок навигации.** Не 11 из референса. `is-active` для открытой панели.
- **Магазин 5/3/2 колонки, 10/6/4 карточки.** Без вертикального скроллбара.
- **Скины: первая покупка — на все предметы, последующие — на один.** Возврат 50% при снятии.
- **Обои наследуются на новых стенах при расширении.** Бесплатно, автоматически.
- **Зум:** только слайдер + кнопка `home`. Без дублирующих `+`/`−`.
- **Сохранения не трогаем:** ключи `moy-restoran:primary/backup/sound`, `schema: 1`, `version: 1`. Новые поля — через `normalizeState`.
- **Не реализуем (в «Кандидатах»):** премиум-валюта, бэкенд, соцфункции, VIP-гости, stacking, отдых персонала.
- **Лимиты дизайна: 5 официантов, 5 стоек выдачи.** Максимум, не больше. Все формулы (`arrivalRate`, `throughput`, `capacity`) оптимизированы под этот диапазон. Эталонная конфигурация 5/5 — нулевой простой; любое отклонение предсказуемо.
- **Скины поваров/плит:** +2 рейтинга, до +5% к скорости готовки (кап). Скины не заменяют прокачку кухни.
- **Распределение официантов по стойкам: детерминированное (`waiterIndex % counters.length`).** Гарантирует, что все официанты работают, но не оптимизирует «ближайшую стойку». Трейд-офф принят. При добавлении/удалении стойки — пересчёт на следующем тике. Если `pickedUp=true` — официант не бросает заказ.

### Технический долг (не блокирует, но помнить)

- **`e2e/progression.spec.ts` смешивает прогрессию и наследование обоев.** Проверяет уровень 5 + `appliedWallpapers` на новых стенах. Работает, но при падении непонятно, какая фича сломалась. Разнести на два spec в будущем (не приоритет).

## Как добавить новый промпт

1. Скопируй шаблон из `docs/prompts/HEADER-TEMPLATE.md` в начало нового файла `docs/prompts/<КОД>.md`.
2. Добавь строку в таблицу промптов выше.
3. Отправь Kimi, поменяй статус на 🔵 Sent.
4. Сохрани ответ в `docs/prompts/responses/<КОД>.md`.
5. После ревью — статус ✅ Accepted или 🔧 Needs Patch.
