# Спецификация анимаций интерфейса

## 1. Статус значений

Значения ниже — **рекомендуемые параметры для нашего UI**, а не измеренные длительности или easing из видео. Ролик показывает смену состояний, но не даёт оснований утверждать точные CSS-параметры оригинала.

Анимации помогают проследить переход и не меняют игровые команды, последовательность покупок, размещение, поворот, награды, сохранения или симуляцию. Не анимируются числа `GameState`, движение гостей/сотрудников и камера в рамках этого UI-этапа.

## 2. Базовые токены

| Назначение | Значение |
|---|---|
| Быстрый отклик | 120–140 мс |
| Выбор/состояние | 160–180 мс |
| Появление панели | 200 мс |
| Скрытие панели | 160 мс |
| Появление | `cubic-bezier(0.2, 0, 0, 1)` — выраженный ease-out |
| Скрытие | `cubic-bezier(0.4, 0, 1, 1)` — выраженный ease-in |
| Изменение состояния | `ease-out` |
| Максимальное смещение панели | 20–24 px |
| Максимальное смещение карточки при hover | 3 px |
| Press-смещение | 2–3 px, без запуска дополнительной команды |

Анимируются преимущественно `transform` и `opacity`. Цвет, рамка и тень могут иметь короткий transition, но не должны вызывать layout. Не анимировать `width`, `height`, `top`, `left`, размеры сетки и DOM всего `GameState`.

|---|---|---|---|---|
| Кнопка: `pointerenter`/hover на устройстве с hover | `transform`, `filter`, при необходимости `box-shadow` | 140 мс `ease-out` | Подъём не более 2–3 px; без бесконечного эффекта. | Повторный hover не суммирует смещение. На touch hover не удерживается искусственно. |
| Кнопка: `pointerdown` / `:active` | `transform`, `box-shadow` | 120 мс `ease-out` | Визуальное нажатие 2–3 px. | Один `click` — один существующий callback. Анимация не задерживает покупку, закрытие или размещение. |
| Кнопка: отпускание / потеря active | `transform`, `box-shadow` | 140 мс `ease-out` | Возврат к hover или обычному состоянию. | Не проигрывать «отпускание» после уничтожения/скрытия элемента. |
| Категория магазина: смена `aria-selected` / `is-active` | Цвет фона, рамка, `transform` не более 2 px | 160 мс `ease-out` | Одновременно выбрана одна категория. | Новый выбор сразу переключает классы; очередь переходов не создаётся. |

| Панель магазина: `open()` | `opacity`, `transform` | 200 мс `cubic-bezier(0.2,0,0,1)` | Текущие `is-open`, непрозрачность и нулевое смещение. | Повторный `open()` идемпотентен; не перезапускает переход без смены состояния. |

| Toast календаря | `opacity`, небольшой `transform` | 180/160 мс | Текст фактической награды; повторное получение ограничено прежней командой. | Повторный клик при доступной награде не дублирует начисление; визуальный переход не управляет наградой. |
| Изменение рейтинга в HUD | `opacity`, цвет существующего `small` | 160 мс `ease-out` | Знак и значение соответствуют состоянию; очистка через текущие 2 секунды. | Новая дельта заменяет предыдущую; таймер перезапускается, без суммирования в DOM. |
| Стрелки возможной пагинации | Отклик кнопки и `opacity` содержимого | 140–160 мс | Меняется только видимая часть существующего списка. | Во время перехода допускается следующий клик, но применяется последнее допустимое состояние; disabled на краях исключает выход за диапазон. |

## 4. Повторные действия и гонки

1. Игровое действие выполняется в обработчике команды, а не по `transitionend`/`animationend`.
2. CSS transition не служит блокировкой кнопки. Недоступность определяется существующими `disabled`, уровнем, балансом, владением и лимитами.
3. Повторное открытие уже открытой панели не создаёт таймеры, классы или обработчики повторно.
4. При закрытии панель сразу становится неинтерактивной, даже если визуальное затухание ещё идёт.
5. При быстром переключении категории видимым и доступным остаётся только последний выбор.
6. Toast не порождает неограниченную очередь; исключение — уже существующая намеренная очередь сообщений о заданиях/уровнях.
7. Обновление состояния не пересоздаёт SVG, карточки и обработчики каждый кадр. Сохранить текущие оптимизации вроде ключа иконки и точечного обновления текста.
8. Анимация не влияет на порядок сохранения `moy-restoran:primary` и `moy-restoran:backup`.

## 5. `prefers-reduced-motion`

Для всех перечисленных компонентов, включая панели, кнопки, карточки, toast, стрелки и подсказки:

```css
@media (prefers-reduced-motion: reduce) {
  /* transition-duration: 0.01ms; animation-duration: 0.01ms;
     animation-iteration-count: 1; либо transition: none для компонента. */
}
```

Обязательное поведение:

- `transform`-переходы, вращение, масштабирование и покачивание отключаются;
- состояние применяется мгновенно; допустим мгновенный переход `opacity`, если он не задерживает ввод;
- ни одна команда не ждёт завершения визуального эффекта;
- видимый фокус, selected, disabled и текстовые статусы сохраняются;
- автоматические бесконечные анимации не вводятся даже для обычного режима.

Существующие правила reduced-motion в `styles.css` и `shopPanel.css` являются базой; при реализации нужно распространить подход на все изменённые компоненты, а не удалять текущие ограничения.

## 6. Приёмка

| Сценарий | Ожидаемый результат |
|---|---|
| Быстро переключить категории 10 раз | Виден последний выбор, один `aria-selected`, нет очереди промежуточных экранов. |
| Несколько раз открыть/закрыть магазин | Нет залипшего `pointer-events`, дублирующих обработчиков или изменения баланса. |
| Кликнуть доступную карточку и сразу другую панель | Команда карточки выполняется один раз; панельная навигация остаётся согласованной с текущей логикой. |
| Завершить размещение через «Готово» и `Escape` | Оба пути завершают прежний режим независимо от длительности скрытия. |
| Получить несколько событий прогресса | Сообщения следуют существующей очередью, не перекрывают управление и не ускоряют игровые события. |
| Включить reduced-motion | Нет движения и масштабирования; все функции и состояния остаются доступными. |
| Ширина 360 px и касание | Нет удержанного hover, сдвига макета и перекрытия целей 44×44 px. |
| Сохранить и загрузить игру после UI-действий | Данные соответствуют прежним командам; анимационные классы и состояния в сохранение не попадают. |
